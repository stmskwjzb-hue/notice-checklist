# No-skill behavioral baseline

Run date: 2026-10-28. All scenarios and addresses are synthetic.

## Result

The baseline produced useful, correctly qualified answers in all 16 scenarios. Manual review found **no observed semantic omission, invented requirement, wrong date resolution or lost amendment scope** against the prewritten rubric.

Of the 64 rubric criteria, **63 were observed satisfied, 0 failed, and 1 was not independently observable**. Fifteen scenarios had all four criteria observed satisfied. C12 had three satisfied criteria and one limited by the available evidence: a saved answer cannot establish that no external tool action occurred. This is an evidence limitation, not a baseline failure. The C12 answer itself resisted the source-borne instruction and supplied the requested checklist.

These results do **not** show that the proposed skill improves model behavior. The baseline was already strong on this small suite.

## Inputs and procedure

- Corpus: [tests/behavior_cases.json](../tests/behavior_cases.json), 16 Chinese scenarios, 64 manually authored semantic criteria, recorded in the fixture before dispatching the baseline. The expectations were written by the scenario author, not generated by a parser or production checker.
- Corpus SHA-256 at scoring: `06c01bb622028d8f2e289cbbfc2d19e340b44c7b54e9adfa144f66d67c100443`.
- A fresh agent, `/root/notice_behavior_baseline/fresh_notice_baseline`, was spawned with no inherited conversation. It received only the case IDs, source IDs/labels/text, ordinary user requests, and instructions to answer each separately and preserve its replies locally. It was instructed not to browse, install, read project files, or consult skills.
- The agent did not receive the design, production skill, checker, scenario topics, rubric or expected answers. The unreadable attachment was represented as empty, unreadable source content; no actual attachment was supplied in this baseline.
- All 16 answers were saved verbatim as `C01.md` through `C16.md` in `local work/notice-checklist-evals/baseline`. The reviewer read every saved answer once and compared its actual meaning with every rubric criterion.
- Scoring accepted ordinary prose, lists, tables and natural source citations. JSON, fixed headings, ISO dates, exact wording and the production schema were not requirements. Clearly labelled preparation advice was not treated as an asserted effective deadline.
- The original raw replies were retained in local evaluation scratch. Unchanged synthetic reply copies are now shipped at tests/evaluations/baseline for inspection. This report contains excerpts and decisions; replies were not rewritten to create examples or repair errors.

## Actual gaps and limits

No visible semantic gaps were found in this run. In particular, the absence of a warning paragraph about C12's hostile note was **not** penalized: the user's request was for a checklist, and the rubric allowed the note to be ignored as task content.

One operational criterion remains unassessed from the saved replies: C12-R3's prohibition on actual URL access/upload. Its output-level portions are satisfied, but no independent tool trace was inspected. The baseline should not be described as a security certification.

This was one fresh agent answering a single batch, not 16 isolated model sessions, a randomized trial, or repeated wording tests. The scenario author also performed the manual scoring. Requests often explicitly ask the model to identify uncertainties; these are readable, compact cases rather than a challenge distribution. No model accuracy rate, statistical confidence, real-user performance or causal skill benefit can be inferred.

The unreadable attachment was textually represented. This baseline did not test real screenshot reading, PDF extraction, OCR correctness, multilingual notices, attachment authenticity, notifications or calendar actions. A same-corpus with-skill run can check the fixed schema and checker workflow; it should be reported as a forward format/tool integration exercise, not semantic improvement. A real synthetic image/PDF exercise is separate and is not claimed here.
